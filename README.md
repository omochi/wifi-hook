# Wi-Fi Hook

接続先の Wi-Fi に応じて、設定したスクリプトを実行する macOS デスクトップアプリ。特定のコマンドや用途に依存しない汎用的な仕組みとする。

## 開発版のビルドとインストール

macOS 27 と Xcode が必要です。Xcode の画面を開かず、リポジトリのルートで次のコマンドを実行すると、Debug ビルドを `~/Applications/WiFiHook.app` にインストールします。同じコマンドで更新できます。

```sh
./scripts/install-dev.sh
```

ビルドと署名の検証が成功してから既存のアプリを置き換えます。アプリが起動中の場合は、終了してから再実行してください。配置後の起動は Finder または `open ~/Applications/WiFiHook.app` で行えます。

現在はローカル実行用のアドホック署名を使用しています。ビルドごとの権限の引き継ぎやログイン時起動は今後検証します。

実ネットワークに接続せずに実行できるロジックのテストは `./scripts/test.sh` で実行します。

## 背景

家とオフィスで開発用サーバーの設定が異なり、移動するたびに手動で `dotenv-switch net.home` / `net.office` を実行している。macOS のショートカットによる自動化も検討したが、GUI で成功・失敗の分岐を組む手間が大きい。

最初の用途は `dotenv-switch` だが、アプリ自体は Wi-Fi とスクリプトの対応を設定できるようにし、他の処理にも使えるようにする。

## 機能

- 設定画面で Wi-Fi 名と、その Wi-Fi に接続したときに実行するスクリプトを登録・編集・削除する。Wi-Fi 名は直接入力するほか、周囲のネットワークや Mac に保存済みのネットワークから選べるようにする。スクリプトの実行に必要な作業ディレクトリも指定できるようにする。
- 起動時とネットワーク変更時に接続先を判定し、登録された Wi-Fi に対応するスクリプトを実行する。
- 接続先が未登録または判定できない場合は、スクリプトを実行せず、通知もしない。
- 設定画面で監視の稼働状態、現在の接続先、最後の実行結果とエラーを確認し、再判定できるようにする。
- 実行の成功・失敗を通知し、通知からアプリを開いて実行結果を確認できるようにする。
- ログイン時に起動できるようにする。

家とオフィスにそれぞれ `dotenv-switch net.home` と `dotenv-switch net.office` を実行するスクリプトを登録するのが最初の用途。対象の checkout や worktree は作業ディレクトリとして明示的に選ぶ。設定の変更が実行中のサーバーに反映されるとは限らず、必要な場合は再起動する。

## 稼働状態の見せ方

メニューバーアイコンは初期状態で表示し、アプリの設定から非表示にできる。設定画面で監視状態と最終実行結果を確認でき、実行結果は通知でも知らせる。

ウインドウを閉じても監視を続ける場合は、そのことと監視を停止する方法を画面上で明確にする。アプリが終了して監視していない状態も区別できるようにする。

## インストールと初回設定

アプリをインストールして起動し、設定画面で Wi-Fi とスクリプトを登録する。監視に必要な位置情報と、実行結果を知らせる通知の許可を案内する。ログイン後も自動的に監視する場合は、アプリの画面からログイン時起動を有効にできるようにする。

Wi-Fi の変更は動作中のアプリが macOS の API で監視する。Wi-Fi ごとに別のフックをシステムへインストールする必要はない。ログイン時起動の登録状態や監視できない理由は画面で確認できる。

スクリプトは `/bin/zsh -c` で実行する。対話シェルの初期化ファイルは読み込まないため、ターミナルでのみ設定した PATH や環境変数が必要な場合は、スクリプト内で指定する。標準出力と標準エラー出力は保存せず、終了状態と実行日時を記録する。監視を停止しても、すでに実行中のスクリプトは終了するまで動作を続ける。

## 開発時に検討すること

- macOS 27 で、SSID 取得に必要な位置情報の許可、通知の許可、ログイン項目を確認する。
- 周囲の Wi-Fi と保存済みネットワークの一覧を取得できる条件や、必要な権限を確認する。
- スクリプトの入力方法や実行環境、複数の登録が同じ Wi-Fi に一致した場合の動作を決める。
- Wi-Fi の切り替え直後の不安定な状態、スリープ復帰、重複イベント、同じ SSID を持つ別ネットワークを考慮する。
- スクリプトの終了状態とエラーを扱い、秘密情報をログや通知に不用意に出さない。
- 複数 worktree の扱い、設定画面の詳細、配布・署名方法は開発時に決める。

現時点の本体実装はビルド済み。Wi-Fi の切り替え、スリープ復帰、通知、ログイン時起動、権限の引き継ぎは実機での確認が必要。
